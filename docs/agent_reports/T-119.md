# Agent Report: T-119 (perf) — Amortized Terrain Chunk Generation

## 1. Problem & Context
In previous profiling under PPSSPP in PSP-1000 mode (`PSPModel = 0`, 32 MB user RAM @ 333 MHz Allegrex MIPS), `Terrain::LoadChunk` executed full evaluation of all 61 vertices along with boundary vertices (`prevVertex`, `nextVertex`), totaling ~550–600 `double` trigonometric operations (`cos`/`sin`), plus Box2D `b2ChainShape` and fixture allocation in a single synchronous function call.
- **Measured baseline latency (T-108):** **10.922 ms** single-frame spike every 30 meters.
- **Impact on 60 FPS budget (16.67 ms):** When combined with Box2D physics solver (~2.1–4.0 ms) and `sceGu` GPU render dispatch (~3.4–6.0 ms), the 10.9 ms spike caused frame drops every ~30 meters of forward travel on PSP hardware.

## 2. Technical Solution: Two-Phase Amortized Pipeline

### (a) Two-Phase Chunk Generation State Machine
Replaced monolithic `LoadChunk` with a fine-grained generation state machine on `TerrainChunk`:
```cpp
struct TerrainChunk {
    int chunkIndex;
    b2Body* body;
    b2Fixture* fixture;
    b2Vec2 vertices[VERTS_PER_CHUNK];
    b2Vec2 prevVertex;
    b2Vec2 nextVertex;
    int verticesComputed;
    uint64_t accumulatedTicks;
    bool ready;
    bool active;
};
```
1. **Incremental Trigonometric Evaluation:**
   - In runtime, `AdvanceGeneration(slotIdx, budget)` evaluates up to $N = 8$ vertices (`CHUNK_GEN_BUDGET = 8`, design/TODO-TUNE) per physics step.
   - Slices are distributed across multiple steps: a 61-vertex chunk completes over $\lceil 61 / 8 \rceil = 8$ physics steps ($\approx 133$ ms at 60 Hz).
2. **Atomic Box2D Chain Creation:**
   - When `verticesComputed == 61`, `nextVertex` is computed, and `b2ChainShape` + `b2Fixture` are created atomically on the preallocated chunk body.
   - `slot.ready = true` is set, and collectible items ahead are spawned.
3. **Proactive Ahead-Chunk Window:**
   - Chunks are maintained in the sliding window $[C - 1, C + 3]$:
     - $C - 1$: Immediate rear boundary (1 chunk).
     - $C$: Under the vehicle (1 chunk).
     - $C + 1, C + 2$: Fully ready ahead buffers (2 chunks, 60 meters of solid terrain).
     - $C + 3$: Background amortized generation slot.
   - Because generation takes only ~8 steps (~4–5 meters traveled at 100 km/h), chunk $C + 3$ completes long before the vehicle ever approaches chunk $C + 2$.
4. **Loading & Safeguard Behavior:**
   - At startup (`Terrain` constructor), initial chunks `[-1, 0, 1, 2]` are completed synchronously (~40 ms during loading screen).
   - In runtime, if an emergency warp occurs such that $c \le C + 1$ is not ready, `CompleteChunkImmediately(slot)` finishes it synchronously as a safeguard.
5. **Render Protection:**
   - `Terrain::Render` only renders chunks that are both `active` and `ready`, preventing partially computed vertex arrays from rendering.
