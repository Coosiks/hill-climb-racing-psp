# Agent Report: T-100 (P0, ci) — CI Integrity & Pipeline Error Propagation

## 1. Goal & Context
The external reviewer noted that previous GitHub Actions CI runs were masking build failures due to unhandled pipeline exit codes (`make ... 2>&1 | tee ...` returns the exit code of `tee`, which is always 0 even if `make` fails).
Task **T-100** establishes strict CI checks:
1. Every step utilizing shell pipes now explicitly uses `shell: bash` with `set -euo pipefail`.
2. PSP build job asserts binary generation via `test -f EBOOT.PBP && test -s EBOOT.PBP` and logs `ls -la` and `sha256sum`.
3. `upload-artifact` enforces `if-no-files-found: error` (failing the job immediately if targets were not generated).
4. PC build job enforces `-DCMAKE_BUILD_TYPE=Release` and runs tests directly without pipe masking.
5. Intentionally exposes compilation/build failures on PSP without masking.

## 2. Changes Made
- Modified `.github/workflows/build.yml`:
  - Added `shell: bash` and `set -euo pipefail` to all `run` steps.
  - Added existence and size verification for `EBOOT.PBP`.
  - Added metadata output (`ls -la EBOOT.PBP hcr.elf` and `sha256sum`).
  - Added `if-no-files-found: error` to artifact uploaders in both `psp-build` and `pc-build`.
  - Configured PC target with `-DCMAKE_BUILD_TYPE=Release`.
  - Updated test runner to execute directly without `tee`.
