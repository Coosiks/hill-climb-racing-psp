## 1. Context & Architectural Problem
The original garage and stage selection implementation suffered from several architectural limitations that blocked expanding the game to the target 1.30.0 version (~29 vehicles, ~27 stages):
1. **Hardcoded UI Layout:** `Game::RenderGarage()` rendered a static 2x2 grid hardcoded to 4 stages (`Countryside`, `Desert`, `Arctic`, `Moon`) and a single vehicle. It had no pagination, tab navigation, or scrolling mechanism.
2. **RAM Exhaustion on PSP-1000 (Lazy Loading Requirement):** `Game::Init()` eagerly preloaded all 4 stage textures (`mTexStageIcons[4]`) into RAM at startup. Expanding this to 27 stages and 29 vehicles with eager preloading would consume over 8–10 MB of RAM, directly threatening the 24 MB usable heap limit on PSP-1000.
3. **Static INI Parsing:** `Config::LoadVehicles()` only populated a single global `VehicleJeep` struct. `Config::LoadStages()` populated a fixed 4-element array without string ID hashes, unlock costs, or dynamic capacity.
4. **Lack of Progression Gating:** Locked stages and vehicles could still be selected and driven. There was no authorization check (`CanStartRace()`) preventing access to unpurchased content.
5. **Disconnected Upgrades:** Upgrading the 4th slot (AWD / Fuel) had no effect on vehicle fuel capacity or range in `PlayerCar`.

## 2. Implemented Architecture

### 2.1 Multi-Section Dynamic Config Parser (`Config.h`, `Config.cpp`)
- Config capacities expanded with capacity constants `MAX_CONFIG_VEHICLES = 32` and `MAX_CONFIG_STAGES = 32`.
- `VehicleConfig` extended with:
  - `id[32]`: String identifier matching INI section header (e.g. `[jeep]`).
  - `unlock_cost`: Coins required to purchase the vehicle (0 for starter vehicle).
  - `base_upgrade_cost`: Base tier cost (default 1000).
  - `max_upgrade_level`: Maximum upgrade level cap (default 20).
  - `upg_mult_fuel`: Multiplier applied per fuel upgrade level (default 1.05).
- `StageConfig` extended with:
  - `id[32]`: String identifier matching INI section header.
  - `unlock_cost`: Coins required to unlock the stage (e.g. 0 for countryside, 10,000 for desert, 20,000 for arctic, 50,000 for moon).
- Full backwards compatibility maintained: `Config::VehicleJeep` is automatically synchronized with `Config::Vehicles[0]`.

### 2.2 Lazy Texture Management (`Texture.h`, `Texture.cpp`)
- Added `Texture::Free()` and `Texture::Destroy()` methods. On PSP, this releases linear VRAM/RAM buffers (`free(mData)`); on PC, this calls `glDeleteTextures(1, &mTexID)`.
- When `LoadTex()` or `LoadPNG()` is called on an existing `Texture` object, it automatically frees existing allocations before loading the new asset.
- In `Game`, eager multi-texture arrays were replaced with single preview cards: `mTexStagePreview` and `mTexVehiclePreview`. Textures are loaded on-demand when scrolling through items in the garage and released immediately when switching cards, maintaining a constant preview texture memory footprint of `< 0.2 MB`.

### 2.3 Scalable Garage Architecture (`Game.h`, `Game.cpp`)
- Garage interface partitioned into 3 distinct tabs switched with `L` and `R` shoulder buttons:
  - `GARAGE_TAB_STAGE` (0): Stage carousel with lock status, unlock cost, best distance record, and one-click purchase (`Cross`/Enter).
  - `GARAGE_TAB_VEHICLE` (1): Vehicle carousel with lock status, unlock cost, and purchase confirmation.
  - `GARAGE_TAB_UPGRADES` (2): 4 upgrade slots (Engine, Suspension, Tires, AWD/Fuel) with level indicators, quadratic cost calculation, and purchase action.
- Dynamic scrolling carousel supporting up to 32 items with bounds clamping and instant visual preview updates.
- Guarded race launch (`CanStartRace()`): Pressing Start or selecting Race verifies that both the selected vehicle and stage are unlocked. Attempting to start on locked content is cleanly rejected.
- Unified race outcome persistence: `CommitRaceResults()` safely writes updated coins and best distance records to `save.bin` via atomic rotation upon race termination or Game Over.

### 2.4 Physics Upgrade Integration (`PlayerCar.h`, `PlayerCar.cpp`)
- `PlayerCar` accepts an optional `const VehicleConfig*` parameter (defaults to `&Config::VehicleJeep`).
- Fuel tank capacity dynamically scales with AWD/Fuel upgrade level:
  $$M_{\text{fuel}} = \text{max\_fuel} \times (\text{upg\_mult\_fuel})^{\text{level}}$$
- Suspension spring frequency scales linearly with suspension tier:
  $$f_{\text{spring}} = f_{\text{base}} + 0.40 \times \text{level}_{\text{susp}}$$
- Engine speed and drive torque scale according to vehicle config parameters.

## 3. Verification & Test Evidence

### 3.1 Unit & Regression Test Suite (`test_garage.cpp`)
A comprehensive regression test harness was created with 5 automated sub-tests covering all aspects of the garage and economy systems:
1. **Subtest 1 (Economy & Unlocking):** Validates coin checks, stage/vehicle purchasing, balance deduction, and rejection when balance is insufficient.
2. **Subtest 2 (Race Start Authorization):** Verifies that `CanStartRace()` rejects unowned stages/vehicles and authorizes only fully unlocked combinations.
3. **Subtest 3 (Upgrade Economy):** Verifies the quadratic cost formula $C(lvl) = 1000 \cdot (lvl+1)^2$, coin deduction, and strict clamping at level 20. Total cost to max out 20 levels is $2,870,000$ coins.
4. **Subtest 4 (Physics Parameter Scaling):** Validates that `PlayerCar` fuel capacity and suspension parameters dynamically reflect upgrade levels.
5. **Subtest 5 (Save/Load Persistence):** Validates roundtrip persistence of unlocked stages, vehicles, best distances, and upgrade tiers through the binary save system (`save.bin`).
