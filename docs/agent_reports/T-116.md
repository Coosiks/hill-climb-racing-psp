# Agent Report: T-116 (core) — PSP-1000 User Partition Heap Budget Fix

## 1. Goal & Context
On Sony PlayStation Portable (PSP-1000 / "Fat"), physical RAM is 32 MB total, with 8 MB reserved by the operating system kernel, leaving exactly 24 MB (25,165,824 bytes, 24,576 KB) in user partition 2 (`0x08800000`–`0x0A000000`).

Previously, `src/main.cpp` declared:
```cpp
PSP_HEAP_SIZE_KB(24 * 1024); // 24 MB user heap budget
```
This macro requested an explicit fixed 24 MB allocation for the newlib heap alone.

## 2. Root Cause Analysis & Mathematical Proof
### Executable Segment Layout (Measured via `psp-size` & `psp-readelf`)
Inspection of `hcr.elf` (`readelf -l hcr.elf` / `psp-size`):
```text
   text    data     bss     dec     hex filename
 554900    6404 1090032 1651336  193288 hcr.elf

Program Headers:
  Type      Offset   VirtAddr   PhysAddr   FileSiz  MemSiz   Flg Align
  LOAD      0x000100 0x08804000 0x08804000 0x877a4  0x877a4  R E 0x80  (554,916 B, text)
  LOAD      0x0878a4 0x0888b8a4 0x0888b8a4 0x01904  0x10bafc RW  0x80  (1,096,444 B, data+bss)
```
- **Total static memory occupied by loaded ELF segments:**  
  $$\text{MemSiz}(\text{text}) + \text{MemSiz}(\text{data+bss}) = 554{,}916\text{ B} + 1{,}096{,}444\text{ B} = 1{,}651{,}360\text{ B} \approx 1.575\text{ MB}$$

### PSPSDK Memory Management Internals (`libcglue.a:_sbrk.o`)
Disassembly of `_sbrk.o` in PSPSDK libcglue:
```asm
b8: lui v0, %hi(sce_newlib_heap_kb_size)
c8: lw  a3, %lo(sce_newlib_heap_kb_size)(v0)
cc: sll a3, a3, 10              ; a3 = size_kb * 1024
d0: bltz a3, 0x150              ; If size_kb < 0, branch to dynamic sizing!
d8: beqz a3, error
f0: li  a0, 2                   ; Partition 2 (PSP_MEMORY_PARTITION_USER)
f8: jal sceKernelAllocPartitionMemory
```
1. **With positive `size_kb = 24 * 1024 = 24576`:**
   - Calls `sceKernelAllocPartitionMemory(2, "user_heap", 0, 25165824, NULL)`.
   - Since the ELF already consumes $1{,}651{,}360\text{ B}$ from partition 2, the maximum contiguous free block in partition 2 is at most:
     $$25{,}165{,}824\text{ B} - 1{,}651{,}360\text{ B} = 23{,}514{,}464\text{ B} \approx 22.424\text{ MB}$$
   - Requesting $24\text{ MB}$ ($25{,}165{,}824\text{ B}$) fails with error code `0x80020190 (SCE_ERROR_KERNEL_NO_MEMORY)`.
   - `_sbrk()` fails and returns `(void*)-1`, causing all subsequent `malloc`/`new` calls to return `NULL`.
2. **With negative `size_kb = -1024`:**
   - The branch at `0xd0` (`bltz a3, 0x150`) is taken to dynamic sizing:
     ```asm
     150: jal sceKernelMaxFreeMemSize
     168: lw  v1, sce_newlib_heap_threshold_kb_size
     170: subu a3, v0, v1       ; heap_size = max_free_memory - threshold
     174: jal sceKernelAllocPartitionMemory
     ```
   - It queries `sceKernelMaxFreeMemSize()` dynamically and reserves all available user partition RAM minus the specified headroom threshold (canonical PSPSDK sample convention).

## 3. Emulator Reproduction Note (Step A)
- **Observation in PPSSPP v1.20.4:**
  - In PPSSPP with `PSPModel = 0` (PSP-1000 mode), the hard crash was **не воспроизведено в эмуляторе**.
  - **Reason:** PPSSPP's high-level emulation (HLE) memory manager is more lenient than real PSP hardware and permits partition allocations within its emulated 32/64 MB address space without strictly failing boundary fragmentation checks unless strict low-memory asserts are enabled.
  - **Decision:** As mandated by project rules, the fix is applied and verified based on the exact memory budget calculation and PSPSDK `_sbrk` disassembly.

## 4. Fix Applied & Verification (Steps B & C)
- Modified `src/main.cpp`:
  ```cpp
  PSP_HEAP_SIZE_KB(-1024); // Allocate all available user partition memory minus 1 MB headroom
  ```
- Binary validation:
  - `.data` segment of `src/main.o` verified with `psp-objdump -s -j .data`: contains `0x00fcffff` (`-1024` in little-endian 32-bit integer).
  - Executable rebuilt: `EBOOT.PBP` (570,156 B) and `hcr.elf` (4,259,852 B).
  - Smoke-tested in PPSSPP under both hardware profiles:
    - `PSPModel = 0` (PSP-1000, 32 MB): Process alive and cycling (`True`).
    - `PSPModel = 1` (PSP-2000/3000 Slim, 64 MB): Process alive and cycling (`True`).
