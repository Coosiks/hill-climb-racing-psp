# Agent Report: T-101 (P0, build) — Fix PSP Build in CI & Environment Normalization

## 1. Goal & Context
The honest CI run from T-100 failed with:
```text
Makefile:75: /opt/pspdev/psp/sdk/lib/build.mak: No such file or directory
make: *** No rule to make target '/opt/pspdev/psp/sdk/lib/build.mak'. Stop.
```
As correctly diagnosed, the official `pspdev/pspdev:latest` Docker image sets `PSPDEV=/usr/local/pspdev`. The workflow previously hardcoded `export PSPDEV=/opt/pspdev`, overriding the container's environment and causing `psp-config --pspsdk-path` to evaluate to a non-existent directory.

Additionally, the reviewer raised a potential issue regarding `strrchr(dir, '')` in `src/main.cpp`.

## 2. Investigation & Diagnostics (Step 1)
### 2.1. Verification of `src/main.cpp`
Inspection of `src/main.cpp` (lines 28–29):
```cpp
char* slash = strrchr(dir, '/');
if (!slash) slash = strrchr(dir, '\\');
```
Verdict: **False positive**. The character literal is correctly escaped as `'\\'` (ASCII 0x5C). The external review tool stripped the backslash when parsing markdown diffs. No code change was needed in `src/main.cpp`.

## 3. Changes Made
1. **`.github/workflows/build.yml` (`psp-build`):**
   - Removed hardcoded `export PSPDEV=/opt/pspdev` and `export PATH`.
   - Added environment diagnostics and sanity checks (`test -f "$(psp-config --pspsdk-path)/lib/build.mak"`).
   - Preserved all T-100 honesty checks (`set -euo pipefail`, artifact verification, `if-no-files-found: error`).
2. **`Makefile`:**
   - Added a pre-include guard that detects missing `build.mak` and fails with an explanatory message:
     ```makefile
     PSPSDK := $(shell psp-config --pspsdk-path)
     ifeq ($(wildcard $(PSPSDK)/lib/build.mak),)
     $(error build.mak not found at $(PSPSDK)/lib — psp-config trusts $$PSPDEV; check your environment)
     endif
     include $(PSPSDK)/lib/build.mak
     ```
3. **`build.sh`:**
   - Removed hardcoded `/opt/pspdev` paths; dynamically queries `psp-config --pspdev-path` if `PSPDEV` is unset.
