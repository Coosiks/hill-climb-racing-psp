## 1. Executive Summary
Task T-032 expands the vehicle architecture of `hill-climb-racing-psp` from a single hardcoded vehicle (Jeep) into a fully data-driven, multi-vehicle system supporting up to 64 distinct vehicles. It integrates the first 4 canonical vehicles extracted in T-120 from Hill Climb Racing APK v1.30.0:
1. **Jeep (Hill Climber)**: All-Wheel Drive (AWD), balanced suspension, 4WD upgrade.
2. **Motocross Bike**: Rear-Wheel Drive (RWD), high rev motor, lightweight chassis, Air Control rotation upgrade.
3. **Monster Truck**: Heavy AWD chassis, oversized tires ($r = 0.65$ m), high torque, 4WD upgrade.
4. **Race Car**: Low-slung aerodynamic chassis, asymmetrical wheel radii (front $r = 0.36$ m, rear $r = 0.42$ m), RWD, high speed ($v_{max} = 45$ m/s), Aerodynamic Downforce upgrade ($F_y \le 150.0$ N).

All 13 regression test suites (including the new `test_vehicles`) pass deterministically on PC. Zero changes to Jeep baselines were required, ensuring 100% backward compatibility.

## 2. Architectural Design & Implementation

### 2.1 VehicleConfig Extensions (`src/core/Config.h`, `Config.cpp`)
The `VehicleConfig` structure was augmented with per-vehicle asset paths, geometric dimensions, drivetrain properties, and 4th-slot specialization parameters:
- `body_texture[64]`, `wheel_texture[64]`, `front_wheel_texture[64]`, `rear_wheel_texture[64]`, `preview_texture[64]`: individual asset paths.
- `front_wheel_radius`, `rear_wheel_radius`: independent radii for front and rear wheels (defaults fallback to `wheel_radius` if unspecified).
- `sprite_width`, `sprite_height`: rendering dimensions for the chassis sprite.
- `drive_type`: `0 = RWD`, `1 = FWD`, `2 = AWD`.
- `fourth_upgrade_type`: `0 = AWD`, `1 = FUEL`, `2 = AIR_CONTROL`, `3 = DOWNFORCE`.
- `downforce_coeff`, `downforce_max`: aerodynamic downforce parameters (Race Car).

Backward compatibility guarantees:
- If `wheel_radius` is specified in legacy configs, it automatically populates both `front_wheel_radius` and `rear_wheel_radius`.
- `Config::VehicleJeep` remains synchronized with `Config::Vehicles[0]`.

### 2.2 Physical Integration in `PlayerCar` (`src/physics/PlayerCar.h`, `PlayerCar.cpp`)
1. **Asymmetrical Axle Dimensions:**
   Front and rear Box2D wheel bodies (`b2CircleShape`) are created with independent radii from `mConfig->front_wheel_radius` and `mConfig->rear_wheel_radius`.
2. **Drive Type Motor Actuation:**
   - **RWD (`drive_type == 0`):** Only the rear `b2WheelJoint` motor is powered; front joint motor is disabled.
   - **FWD (`drive_type == 1`):** Only the front `b2WheelJoint` motor is powered; rear joint motor is disabled.
   - **AWD (`drive_type == 2`):** Rear joint is always powered with `(1.0 - awdFactor)`; front joint is powered with `awdFactor` if AWD level $> 0$ (or if slot 4 is non-AWD).
3. **Specialized 4th-Slot Upgrades:**
   - **Air Control (`fourth_upgrade_type == 2`):** `air_pitch_torque` scales dynamically with slot 4 level:
     $$\tau_{air} = \tau_{base} \times (1.0 + 0.06 \times \text{level})$$
   - **Aerodynamic Downforce (`fourth_upgrade_type == 3`):** Produces vertical downforce proportional to the square of horizontal velocity, clamped to prevent suspension collapse:
     $$F_y = -\min(\text{coeff} \cdot (1.0 + 0.10 \times \text{level}) \cdot v_x^2, \; 150.0\text{ N})$$
     Applied directly to chassis center of mass via `mChassis->ApplyForceToCenter()`.
   - **Fuel Capacity (`fourth_upgrade_type == 1`):** Tank capacity scales with `powf(upg_mult_fuel, level)`.

### 2.3 Garage UI Dynamic Adaptations (`src/core/Game.cpp`)
- **Dynamic Preview Loading:** `LoadVehiclePreview()` selects `preview_texture` from the active vehicle configuration, falling back to `body_texture` or default.
- **Dynamic 4th Slot Tuning Tab:** In `RenderGarage()`, the 4th upgrade card dynamically updates its label and control hint according to `fourth_upgrade_type`:
  - `0`: `"4WD"` (`[SEL] 4WD`)
  - `1`: `"FUEL"` (`[SEL] FUEL`)
  - `2`: `"AIR CTRL"` (`[SEL] AIR`)
  - `3`: `"DOWNFORCE"` (`[SEL] DOWN`)
