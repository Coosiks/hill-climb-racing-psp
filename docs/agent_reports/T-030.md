# Agent Report: T-030 — Robust Binary Save System

## Summary
- **Task:** T-030: Robust Binary Save System with IEEE 802.3 CRC32, FAT32-Safe Atomic Rotation, MIPS Natural Alignment, and Legacy Migration.
- **Milestone:** M0.2 / M6 Progress Foundation.
- **Status:** Completed & Verified.

---

## 1. Context & Architectural Problem
The previous save implementation (`save.dat`, magic `0x48435231` `'HCR1'`) suffered from critical vulnerabilities:
1. **Lack of Integrity Verification:** No checksum or payload length in header; single-byte corruption or incomplete write led to game crash or zeroed user progress.
2. **Hardware Alignment Trap on MIPS:** On PSP's Allegrex MIPS CPU, unaligned 32-bit reads/writes trigger hardware Address Error Exceptions.
3. **FAT32 `rename()` Failure:** In PSPSDK and Windows, `rename(old, new)` fails with error if `new` already exists (unlike Linux POSIX).
4. **Memory Stick Wear & Stalls:** Synchronous I/O occurred on unverified state without dirty tracking.
5. **Rigid Schema:** Hardcoded 1 car and 4 stages by array index, blocking expansion to the 1.30.0 target (~29 vehicles, ~27 stages).

---

## 2. Implemented Architecture

### 2.1 Pure IEEE 802.3 CRC32 & FNV-1a 32-bit Hashing
- Fast table-driven CRC32 implementation using canonical polynomial `0xEDB88320`.
- FNV-1a 32-bit string hashing (`HashId()`) for vehicle and stage string IDs, decoupling save records from config array indices.

### 2.2 Strict 4-Byte Natural Alignment
All binary structures feature explicit padding fields and compile-time verification:
- `SaveHeader` (16 bytes, offset 0, mod 4 == 0)
- `SavedVehicleEntry` (12 bytes, mod 4 == 0)
- `SavedStageEntry` (12 bytes, mod 4 == 0)
- `SavePayload` (1556 bytes, mod 4 == 0, holding up to 64 vehicles and 64 stages)
- Compile-time guarantees via `static_assert(sizeof(...) % 4 == 0)` and field offset alignment checks (`offsetof(...) % 4 == 0`).

```cpp
#pragma pack(push, 1)
struct SaveHeader {
    char     magic[4];        // 'H','C','R','S' (0x53524348)
    uint16_t version;         // 1
    uint16_t flags;           // 0
    uint32_t payloadSize;     // 1556
    uint32_t crc32;           // CRC32 of payload
};

struct SavedVehicleEntry {
    uint32_t idHash;          // offset 0 (4 bytes)
    uint8_t  unlocked;        // offset 4 (1 byte)
    uint8_t  levelEngine;     // offset 5 (1 byte)
    uint8_t  levelSuspension; // offset 6 (1 byte)
    uint8_t  levelTires;      // offset 7 (1 byte)
    uint8_t  level4th;        // offset 8 (1 byte: AWD or Fuel)
    uint8_t  reserved[3];     // offset 9..11 (3 bytes padding)
};

struct SavedStageEntry {
    uint32_t idHash;          // offset 0 (4 bytes)
    uint8_t  unlocked;        // offset 4 (1 byte)
    uint8_t  reserved[3];     // offset 5..7 (3 bytes padding)
    int32_t  bestDistance;    // offset 8 (4 bytes)
};

struct SavePayload {
    int64_t           coins;                 // offset 0 (8 bytes)
    uint32_t          selectedVehicleIdHash; // offset 8 (4 bytes)
    uint32_t          selectedStageIdHash;   // offset 12 (4 bytes)
    uint16_t          vehicleCount;          // offset 16 (2 bytes)
    uint16_t          stageCount;            // offset 18 (2 bytes)
    SavedVehicleEntry vehicles[64];          // offset 20 (768 bytes)
    SavedStageEntry   stages[64];            // offset 788 (768 bytes)
};
#pragma pack(pop)
```

### 2.3 FAT32 Safe Atomic Rotation
```
1. Write save.tmp -> fflush() -> fclose()
2. Read-verify save.tmp (magic + version + payloadSize + CRC32 check)
3. If save.bin exists: remove(save.bak) -> rename(save.bin, save.bak)
4. remove(save.bin) -> rename(save.tmp, save.bin)
5. Clear dirty flag (sDirty = false)
```

### 2.4 Automatic Recovery & Legacy Migration
- **Corruption Recovery:** If `save.bin` fails CRC32 verification, `PlayerInfo::Load()` falls back to `save.bak`.
- **Legacy Migration:** If no `save.bin` or `save.bak` exists, checks for `save.dat` (`'HCR1'`). If valid, migrates coins, Jeep upgrades, and stage records into the new format and commits `save.bin` immediately.
