## 2. Color Packing Parity Audit: PSP `GU_COLOR_8888` vs PC `OpenGL`

### 2.1 Color Representation Architecture
In `config/stages.cfg`, sky and terrain colors are stored as 32-bit hex values in `0xAABBGGRR` format (e.g. Mars sky top `0xFF182888`, Countryside `0xFFD87820`).

On the Sony PSP hardware:
- The Graphical Engine (GE) in `GU_COLOR_8888` mode expects the color payload in little-endian Allegrex memory as:
  - Byte 0: Red ($c \ \& \ \text{0xFF}$)
  - Byte 1: Green ($(c \gg 8) \ \& \ \text{0xFF}$)
  - Byte 2: Blue ($(c \gg 16) \ \& \ \text{0xFF}$)
  - Byte 3: Alpha ($(c \gg 24) \ \& \ \text{0xFF}$)

On the PC OpenGL target (`src/graphics/Renderer2D.cpp`):
```cpp
static inline void SetGLColor(unsigned int c) {
    glColor4ub(c & 0xFF, (c >> 8) & 0xFF, (c >> 16) & 0xFF, (c >> 24) & 0xFF);
}
```
All OpenGL primitives (`FlushBatch()`, `DrawFilledRect()`, `DrawGradientRect()`, `DrawTerrainFill()`, and `DrawTerrainSurface()`) pass the color through `SetGLColor(color)`.

### 2.2 Invariant Documentation
The canonical format invariant was permanently documented in `src/graphics/Renderer2D.h`:
```cpp
// Standard 32-bit color format across PSP and PC: 0xAABBGGRR (ABGR)
// Matches hardware GU_COLOR_8888 on little-endian PSP and OpenGL glColor4ub:
//   Byte 0 (bits  0- 7): Red
//   Byte 1 (bits  8-15): Green
//   Byte 2 (bits 16-23): Blue
//   Byte 3 (bits 24-31): Alpha
```

## 3. Asymmetrical Wheel Rendering in `PlayerCar::Render()`

### 3.1 Verification of Radii and Textures
Vehicles in Hill Climb Racing 1.30.0 exhibit distinct front and rear wheel dimensions (e.g. Tractor: front `0.35m`, rear `0.60m`; Race Car: front `0.36m`, rear `0.42m`).

In `src/physics/PlayerCar.cpp`:
- **Texture Loading:**
  ```cpp
  const char* rearTireTex = (mConfig && mConfig->rear_wheel_texture[0]) ? mConfig->rear_wheel_texture :
                            ((mConfig && mConfig->wheel_texture[0]) ? mConfig->wheel_texture : "assets/Tire.png");
  const char* frontTireTex = (mConfig && mConfig->front_wheel_texture[0]) ? mConfig->front_wheel_texture :
                             ((mConfig && mConfig->wheel_texture[0]) ? mConfig->wheel_texture : "assets/Tire.png");
  mTexTire.LoadPNG(rearTireTex);
  mTexFrontTire.LoadPNG(frontTireTex);
  ```
- **Rendering Pass:**
  ```cpp
  // Rear Wheel:
  float rearRadius = (mConfig->rear_wheel_radius > 0.0f) ? mConfig->rear_wheel_radius : mConfig->wheel_radius;
  float diameter = rearRadius * 2.0f;
  Renderer2D::DrawSprite(&mTexTire, pos.x, pos.y, diameter, diameter, angle);

  // Front Wheel:
  float frontRadius = (mConfig->front_wheel_radius > 0.0f) ? mConfig->front_wheel_radius : mConfig->wheel_radius;
  float diameter = frontRadius * 2.0f;
  Renderer2D::DrawSprite(&mTexFrontTire, pos.x, pos.y, diameter, diameter, angle);
  ```

### 3.2 Regression Verification
Verified via `test_vehicles` Box2D simulation:
- Tractor front wheel diameter $= 0.70$ m, rear wheel diameter $= 1.20$ m.
- Race Car front wheel diameter $= 0.72$ m, rear wheel diameter $= 0.84$ m.
Both front and rear wheels render with exact matching collision geometry and independent textures.
