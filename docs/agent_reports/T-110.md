# Agent Report: T-110 (core) — Config Unification (Single Source of Truth)

## 1. Goal & Context
Previously, external configuration files (`config/*.cfg`) were partially parsed, but core runtime systems (`PlayerCar.cpp`, `Game.cpp`, `PhysicsWorld.cpp`, `Terrain.cpp`) consumed hardcoded `#define` values from `GameConstants.h`. Furthermore, several critical keys (`chassis_vertex_count`, `v0`..`v5`, `driver_head_radius`, `driver_head_offset`, `upgrade_mult_*`, `zoom_*`, `music`) were completely ignored by `Config.cpp`. Editing the `.cfg` files had no effect on game physics or gameplay rules.

## 2. Architecture & Implementation
1. **Full Config Coverage (Parsing All Ignored Keys):**
   - **`physics.cfg` [camera]:** Added `zoom_base` ($1.0$), `zoom_speed_factor` ($0.005$), `min_zoom` ($0.8$), `max_zoom` ($1.2$) to `PhysicsConfig` and `Config::LoadPhysics`.
   - **`vehicles.cfg` [jeep]:** Added `chassis_vertex_count`, `v0`..`v7` vertex coordinates (using robust comma parsing immune to whitespace), `driver_head_radius`, `driver_head_offset`, `upgrade_mult_engine`, `upgrade_mult_suspension`, `upgrade_mult_tires`, `upgrade_mult_awd` to `VehicleConfig` and `Config::LoadVehicles`.
   - **`stages.cfg`:** Added `name` and `music` to `StageConfig` and `Config::LoadStages`.
2. **Replacing `#define`s with `Config` Across All Consumers:**
   - **`PlayerCar.cpp`:**
     - Chassis polygon vertices and count read from `Config::VehicleJeep.chassis_vertices` and `Config::VehicleJeep.chassis_vertex_count`.
     - Chassis density, friction, restitution read from `Config::VehicleJeep`.
     - Wheel radius, density, base friction, restitution, and wheel offsets read from `Config::VehicleJeep`.
     - Suspension frequency and damping read from `Config::VehicleJeep`.
     - Driver head offset and radius read from `Config::VehicleJeep`.
     - Motor speed, torque, upgrade multipliers, and airborne pitch torque read from `Config::VehicleJeep`.
     - Fuel capacity and drain rates read from `Config::Physics`.
   - **`Game.cpp`:**
     - Camera lookahead (`camera_lead_x`, `camera_lead_y`) and smoothing (`camera_smoothing`) read from `Config::Physics`.
     - Dynamic speed-based camera zoom implemented using `Config::Physics.zoom_base`, `zoom_speed_factor`, `min_zoom`, `max_zoom`.
     - Stunt rewards read from `Config::Physics.flip_bonus_coins`.
     - Stage gravity loaded data-driven from `Config::Stages[mCurrentStage].gravity`.
     - HUD fuel gauge normalized against `Config::Physics.max_fuel`.
   - **`PhysicsWorld.cpp`:**
     - Box2D velocity and position iterations read from `Config::Physics.velocity_iterations` and `Config::Physics.position_iterations`.
   - **`Terrain.cpp`:**
     - Surface friction and coin multiplier query `Config::Stages[mStageType].friction` and `Config::Stages[mStageType].coin_multiplier`.
     - Ground and surface texture paths read directly from `Config::Stages`.
3. **`GameConstants.h` Cleanup:**
   - Retained only fixed immutable parameters: screen dimensions ($480 \times 272$), `PTM_RATIO` ($32.0$), collision category bitmasks (`CAT_*`), stage enums (`StageType`), and upgrade price formula.
   - All tunable physics constants labeled as fallback defaults for backward compatibility with isolated test harnesses.
4. **Preserved Baseline Defaults:**
   - Default struct initializers in `Config.cpp` match baseline values to ensure identical out-of-the-box behavior.

## 3. Regression Test Verification (`tools/test_config.cpp`)
A dedicated automated test was created and integrated into CMake and CI:

### Sub-test 1: Baseline Defaults Verification
- Verified all default fields of `Config::Physics`, `Config::VehicleJeep`, and `Config::Stages[0..3]`.
- Result: **PASS** (100% exact match).

### Sub-test 2: Full Key Coverage (52 Keys)
- Tested every key across all three configuration files by generating a temporary `.cfg` file with a distinct modified value, reloading, and asserting the struct field updated:
  - `physics.cfg`: 17 / 17 keys covered.
  - `vehicles.cfg`: 28 / 28 keys covered.
  - `stages.cfg`: 7 / 7 keys covered.
- Total keys tested: **52 / 52** | Uncovered keys: **0**.
- Result: **PASS**.

### Sub-test 3: Dynamic Behavior Change Without Recompilation
- Spawned `PlayerCar` with baseline config: mass = $3.41\text{ kg}$, wheel radius = $0.40\text{ m}$.
- Generated temporary custom vehicle config setting `chassis_density = 4.5` and `wheel_radius = 0.65`.
- Reloaded via `Config::LoadVehicles("tmp_custom_vehicle.cfg")` without recompiling code.
- Spawned second `PlayerCar`: mass = $10.23\text{ kg}$, wheel radius = $0.65\text{ m}$.
- Result: **PASS** (runtime physical behavior dynamically reflects config edits).
