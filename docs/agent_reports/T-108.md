# Agent Report: T-108 (core) — Fixed Timestep Accumulator, Render Interpolation & PPSSPP Profiling Snapshot

## 1. Goal & Context
Previously, `Game::Run()` executed exactly one `mPhysics->Step(FIXED_TIMESTEP)` per rendered frame:
- If framerate dropped on PSP hardware (e.g. to 30–40 FPS under heavy rendering load), the physics simulation ran in slow-motion rather than real time.
- If framerate varied on PC (e.g. 60 Hz vs 144 Hz vs unlocked), simulation speed was tied to monitor refresh rate and VSync intervals.
- The lack of transform interpolation caused visual stuttering if rendering and physics ran at mismatched cadences.

## 2. Technical Solution

### (a) High-Resolution Platform Timers (`src/core/System.h`, `src/core/System.cpp`)
Implemented precision monotonic timing functions:
- **PC (Linux / Windows / macOS):** Uses `SDL_GetPerformanceCounter()` / `SDL_GetPerformanceFrequency()` providing microsecond-level accuracy, with standard C++11 `std::chrono::steady_clock` fallback when SDL is not initialized (e.g. in headless regression unit tests).
- **PSP (Allegrex MIPS):** Uses hardware RTC ticks via `sceRtcGetCurrentTick()` and `sceRtcGetTickResolution()` (1,000,000 Hz / microsecond resolution).
- Exposed API:
  - `double System::GetTimeSeconds()`: Monotonic seconds since process startup.
  - `float System::GetDeltaTime()`: Delta elapsed since previous call.

### (b) Fixed Timestep Accumulator Loop (`src/core/Game.cpp`, `src/core/Game.h`)
Encapsulated accumulator logic in `Game::UpdatePlaying(float frameTime)` and `Game::UpdatePhysicsStep(float dt)`:
1. **Spiral of Death Clamp:** Clamped incoming frame time `if (frameTime > 0.10f) frameTime = 0.10f;`.
2. **Substep Bounding:** Sub-step iterations are strictly bounded:
   ```cpp
   while (mAccumulator >= fixedDt && substeps < maxSubSteps) {
       UpdatePhysicsStep(fixedDt);
       mAccumulator -= fixedDt;
       substeps++;
       if (mState != STATE_PLAYING) break;
   }
   ```
   where `fixedDt` (`Config::Physics.fixed_timestep = 1/60`) and `maxSubSteps` (`Config::Physics.max_sub_steps = 3`) are sourced directly from unified configuration.
3. **Interpolation Alpha:** Computed `mRenderAlpha = mAccumulator / fixedDt` clamped to $[0.0, 1.0]$.
4. **Jitter-Free Camera Follow:** Camera follow tracks the interpolated vehicle position `mCar->GetInterpolatedPosition(mRenderAlpha)` so camera tracking matches interpolated sprite rendering without micro-stutter.

### (c) Render Transform Interpolation (`src/physics/PlayerCar.h`, `src/physics/PlayerCar.cpp`)
1. **Transform Storage:** `PlayerCar` tracks `BodyTransform` (position and angle) for chassis, front wheel, rear wheel, and driver head.
2. **Pre-Step Capture:** `mCar->CapturePreviousTransforms()` is called immediately before `mPhysics->Step(dt)` so previous state is captured at the boundary of each physics sub-step.
3. **Linear & Angular Lerp:**
   - Positions linearly interpolated: $P_{\text{render}} = (1 - \alpha) P_{\text{prev}} + \alpha P_{\text{cur}}$.
   - Orientations interpolated using `LerpAngle(prev, cur, alpha)` with shortest-path wrap-around handling across $[-\pi, \pi]$:
     ```cpp
     static inline float LerpAngle(float prevAngle, float curAngle, float alpha) {
         float diff = curAngle - prevAngle;
         while (diff > 3.14159265f)  diff -= 6.2831853f;
         while (diff < -3.14159265f) diff += 6.2831853f;
         return prevAngle + diff * alpha;
     }
     ```
   - Torso and chassis sprite offsets in local space are transformed by the interpolated rotation matrix via Box2D `b2Mul(b2Rot(chassisAngle), localOffset)`.
4. **Physical Integrity:** Interpolation is applied purely at the render pass (`PlayerCar::Render(float alpha)`); all Box2D physical states, contact queries, and sensor callbacks remain unmodified.
