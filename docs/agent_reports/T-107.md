# Agent Report: T-107 (physics) — Sliding Window b2ChainShape Terrain Chunks

## 1. Goal & Context
The previous terrain implementation maintained a monolithic Box2D body with individual `b2EdgeShape` fixtures. This had three major drawbacks:
1. **Ghost Collisions:** Individual edge fixtures lack adjacent vertex connectivity, causing wheel circles to snag on internal vertices ("ghost collision").
2. **Dynamic Body/Fixture Thrashing:** Rebuilding fixtures or allocating unbounded points caused memory fragmentation on the PSP's limited heap.
3. **Trigonometric Load During Rendering:** Rendering previously called `GetHeightAtX` repeatedly across screen coordinates instead of reusing physics vertex coordinates.

## 2. Architecture & Implementation
1. **b2ChainShape with Connectivity:**
   - Chunks are sized at $30.0\text{ m}$ (`CHUNK_WIDTH_METERS = 30.0f`, step $0.5\text{ m}$, $61\text{ vertices}$ per chunk).
   - Each chunk fixture is created using `b2ChainShape::CreateChain()`.
   - Adjoining boundary continuity is ensured via `b2ChainShape::SetPrevVertex()` ($startX - 0.5\text{ m}$) and `b2ChainShape::SetNextVertex()` ($endX + 0.5\text{ m}$). This provides internal normal continuity to Box2D's circle-vs-chain solver, eliminating seam ghost collisions.
2. **Fixed Static Chunk Pool (Zero Runtime Allocations):**
   - Preallocated static body array: `TerrainChunk mChunks[NUM_CHUNK_SLOTS]` (`NUM_CHUNK_SLOTS = 6`).
   - Bodies are created once in `InitChunkPool()`. At runtime, chunks are activated and updated in-place via `slot.body->CreateFixture(&fd)` and `slot.body->DestroyFixture()`. No Box2D bodies are allocated or freed during gameplay.
3. **Sliding Window:**
   - `UpdateChunkWindow(currentChunk)` keeps chunks in range $[currentChunk - 1, currentChunk + 2]$ active (spanning $[-30\text{ m}, +90\text{ m}]$ around the player). Chunks outside this window are deactivated and their fixtures destroyed.
4. **Dedicated Rear Boundary Wall:**
   - A dedicated static body `mRearWallBody` is placed at $X = -20.0\text{ m}$ with vertical span $Y \in [-15.0\text{ m}, 35.0\text{ m}]$, with zero friction (`0.0f`) to prevent the car from falling off the start.
5. **Stage-Specific Surface Friction:**
   - Fixture friction is assigned per stage: Countryside (`0.60`), Desert (`0.50`), Arctic (`0.15`), Moon (`0.80`).
6. **Cached Vertex Rendering:**
   - `Render()` directly reads pre-computed vertices from the active `mChunks` into `mRenderX`/`mRenderY` without calling `GetHeightAtX()` during the rendering pass, eliminating trigonometric calculations from the render loop.
