# Task Report: H17b — Music Path Normalization & Mono 22050Hz Enforcement

## 1. Problem Statement & Findings
1. **Broken Extension Fallback in PlayMusic:**
   - `config/stages.cfg` references original asset paths (`assets/audio/bgmusic00.ogg`, `assets/audio/bgmusic01.ogg`).
   - `AudioEngine::PlayMusic` checked `fopen(filepath, "rb")`. Because the `.ogg` files exist on disk, `fopen` succeeded on the `.ogg` file.
   - The file header read checked for `"RIFF....WAVE"`. Since OGG files start with `"OggS"`, the RIFF validation failed, closing the file and returning `false`.
   - The fallback branch replacing `.ogg` with `.wav` was never executed because `f` was not NULL.
2. **Channel Specification Invariant:**
   - The streaming music ring buffer (`UpdateMusicStream`) and mixer read raw 16-bit PCM samples into the mono ring buffer.
   - Any stereo audio would cause sample interleaving and playback speed anomalies. Audio conversion must guarantee mono 16-bit PCM at 22050 Hz.

## 2. Changes Implemented

### 2.1 Audio Path Normalization & RIFF Verification
- Introduced `TryOpenWavFile(const char* path)` in `src/audio/AudioEngine.cpp`:
  - Opens file, verifies 12-byte `"RIFF....WAVE"` header signature.
  - If invalid or not present, closes file and returns NULL.
  - If valid, returns file pointer positioned at offset 12 ready for chunk parsing.
- Implemented robust fallback logic in `AudioEngine::PlayMusic`:
  1. Try `filepath` directly.
  2. If NULL or not RIFF/WAVE, try replacing `.ogg` with `.wav` (or `.wav` with `.ogg`).
  3. On PSP targets (`__PSP__`), try prepending `"ms0:/PSP/GAME/HCR/"` with both extensions.
  4. Enforced strict validation: `channels == 1` (mono), `bitsPerSample == 16`, `sampleRate > 0`.

### 2.2 Asset Converter & Design Documentation
- Ensured `tools/convert_assets.py` converts all audio to mono 22050Hz 16-bit PCM WAV (`-ac 1 -ar 22050 -c:a pcm_s16le`).
- Documented in `docs/params.csv` and `docs/ROADMAP.md` that all 28 stages are currently mapped to the two generic tracks (`bgmusic00` / `bgmusic01`), matching the 1.30.0 default behavior; extraction of distinct stage themes from `libgame.so` is catalogued for future expansion.

## 3. Verification & Results

  - Stages 0–27: 100% (28 / 28) returned `true` and successfully initialized music streaming.
