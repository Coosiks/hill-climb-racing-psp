## 1. Context & Architectural Challenge
Transitioning the native C++/PSP homebrew port from prototype scope (v1.0.5, 1 car, 4 stages) to commercial release parity with v1.30.0 required a comprehensive inventory of all game content:
1. **Stripped Symbols:** In production Android release builds, `.dynsym` removes all internal C++ function and variable symbols.
2. **Reverse Engineering Invariance:** To prevent hallucinated numbers, all physical parameters, unlock costs, and sprite paths must have strict provenance traced back to binary addresses in `libgame.so`.
3. **Asset Scale:** v1.30.0 contains 1,152 assets (939 PNG textures), exceeding prototype volume by an order of magnitude.

---

## 2. Implemented Tooling & Deliverables

### 2.1 Automated Extraction Script (`tools/extract_1300_info.py`)
Developed a standalone CLI tool that accepts `--apk` or `--so` arguments (with zero hardcoded local directory paths):
- Reconstructs demangled C++ RTTI class names for all `PlayerCar*` and `Stage*` entities.
- Disassembles x86 registration routines via Capstone:
  - Vehicle registration call at `0xf488c` across `0xf6900`–`0xfb500` (extracting `vid`, title string, preview icon string, unlock cost, and disassembly address).
  - Stage registration call at `0x14a2b0` across `0x14c2f8`–`0x14f500` (extracting `id`, title string, icon string, and unlock cost).
- Generates reproducible, auditable dump at `docs/bench/re_1300_dump.txt`.
